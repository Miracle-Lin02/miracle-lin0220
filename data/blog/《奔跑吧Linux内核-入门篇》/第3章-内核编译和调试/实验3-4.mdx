    ```

    !STACK
    ```

### A1.
    Ubuntu 源自带的 eclipse 3.8 太老旧，和现代 Java 完全不兼容，需要自己另外下载安装

    1. 卸载损坏的 eclipse
    ```
    sudo apt remove eclipse eclipse-cdt
    sudo apt autoremove
    # 删除旧的eclipse缓存目录
    rm -rf ~/.eclipse
    ```
    2. 安装书本指定 Eclipse Oxygen 4,7,3a(Oxygen3, IDE for C/C++)
    ```
    cd ~/Downloads
    wget https://download.eclipse.org/technology/epp/downloads/release/oxygen/3a/eclipse-cpp-oxygen-3a-linux-gtk-x86_64.tar.gz
    tar -zxvf eclipse-cpp-oxygen-3a-linux-gtk-x86_64.tar.gz -C ~/
    ```
    3. 运行 Eclipse
    ```
    ~/eclipse/eclipse
    ```

### Q2.
    运行 Eclipse 报错 java.lang.NoClassDefFoundError: javax/annotation/PreDestroy
### A2.
    报错原因：当前系统用的是 Java11，Jaca11 移除了 javax.annotation 包，而 Eclipse Oxygen 依赖这个包，所以需要用 Java8
    1. 安装 Java8
    ```
    sudo apt update
    sudo apt install openjdk-8-jdk
    ```
    2. 切换 Java 版本
    ```
    sudo update-alternatives --config java
    ```
    选择 Java8
    3. 验证当前 java 版本
    ```
    java -version
    ```
    4. 启动 Eclipse
    ```
    ~/eclipse/eclipse
    ```

### Q3.
    AARch64 平台调试时，gdb8.1.1存在寄存器包截断 bug，continue无法执行
### A3.
    原因：Ubuntu18.04的gdb-multiarch 8.1.1 不支持 AArch64的GDB远程协议，寄存器数据包解析失败。

    解决办法：切换为ARM32（vexpress-a9）平台编译内核，gdb8.1.1支持ARM32远程调试，没有这个bug。

    书上用的就是 ARM32，我自己把runninglinuxkernel包重新下了一遍，编译内核成 ARM64 了TAT

### Q4.
    Eclipse GDB 远程调试报错：vMustReplyEmpty timeout
### A4.
    1. Eclipse CDT默认使用extended-remote扩展远程调试协议；

    2. Ubuntu18.04自带QEMU版本老旧，内置gdbstub没有完整实现extended-remote扩展包，无法响应vMustReplyEmpty能力探测包，握手超时；

    3. 命令行target remote是基础协议，不需要这套扩展探测包，所以命令行gdb可以正常连接。

    解决办法：放弃Eclipse图形调试，使用命令行gdb-multiarch完成远程断点调试，成功在start_kernel函数命中断点，完成实验目标。

    如果想使用 Eclipse 图形调试的话只能使用更新版本的系统了
